### 1. Assessment of the Refactoring Plan ([plan.md](./plan.md))

1. **Architecture Choice (Unit 1):** Preferring local domain state types over a universal state-machine framework is essential. `messpy` enforces strict self-analysis gates ([verify_self_analysis.py](../../../scripts/verify_self_analysis.py#L109-L134) and [messpy-onion.xml](../../../rulesets/messpy-onion.xml#L6-L13)), including `LackOfCohesionOfMethods` ($\text{LCOM4} \le 1$), `CouplingBetweenObjects` ($< 13$), `CyclomaticComplexity` ($< 10$), `NPathComplexity` ($< 200$), `DomainAction`, and `explicitness`. A generic transition engine or mutable state classes will immediately fail self-analysis (`ImplicitInstanceOutput`, `UnknownEffect`, or `CouplingBetweenObjects`).
2. **Existing Explicit Machines vs. True Gaps (Unit 2):** Since the 16-module inventory was taken, `main` (`3448957`) has already extracted 4 modules (`callables.py`, `parameters.py`, `regions.py`, `syntax.py`) and partially or fully reified several machines (e.g., `_ArgumentParseState` in `cli.py`, `_ConfiguredRule` in `rulesets.py`, `_BindState`/`_CallableIndex` in `callgraph.py`, `_State`/`_Flow`/`_Context` in `ownership.py`, `_NamingState` in `analyzer.py`). Unit 2 should classify each of `M01`–`M39` into:
   - **Verify & Tighten:** State carrier already exists; make transitions named functions/methods and eliminate remaining ad-hoc tuple/flag threading.
   - **Consolidate & Reify:** State is currently split across parallel dicts, multi-return tuples, or duplicated across modules (`M09` lexical lookup, `M25`–`M26` suppressions, `M27` globals, `M28` private members, `M31` onion propagation, `M38` first-witness deduplication).
3. **Worktree Partitioning Risk (Units 3–5):** [analyzer.py](../../../src/messpy/analyzer.py) is a 5,116-line hub touched by Units 3, 4, and 5 (`_ScopeChain` and `_ownership_program` for Unit 3; `_source_files` and `_apply_suppressions` for Unit 4; `_naming_roles`, `_function_scopes`, `_private_member_usage`, `_global_variable_findings`, `_has_boolean_result`, `_ast_visitor_class_ids` for Unit 5). Parallel workers editing `analyzer.py` across Units 3–5 will cause severe merge conflicts unless either `analyzer.py` edits are serialized in Unit 6 or the newly reified state machines are extracted into dedicated domain helpers imported by `analyzer.py` (warning: any new `.py` file under `src/messpy/` must also be added to the `domain` glob list in [messpy-onion.xml](../../../rulesets/messpy-onion.xml#L9)).

### 2. Concrete Authoritative State Representations (`M01`–`M39`)

All state carriers in domain modules **must** be `@dataclass(frozen=True)` with pure transition functions (`(State, Event) -> State`)—never in-place mutations (`self.x = ...`), which violate `ImplicitInstanceOutput` / `DomainAction`, and never methods on dataclasses that are instantiated inside analyzed functions (see Pitfall 1 below).

### 3. Semantic & Verification Pitfalls to Warn Against

1. **PITFALL (Self-Analysis Breaker): Adding methods or `default_factory` fields to `@dataclass(frozen=True)` records in domain modules.**
   - Look at `_frozen_record` and `_record_field` in [effects.py](../../../src/messpy/effects.py#L436-L453):
     ```python
     def _record_field(statement: ast.stmt) -> bool:
         if isinstance(statement, ast.AnnAssign) and isinstance(statement.target, ast.Name):
             return statement.value is None or isinstance(statement.value, ast.Constant)
         return isinstance(statement, ast.Pass) or isinstance(statement, ast.Expr) and isinstance(statement.value, ast.Constant)
     ```
   - `messpy`'s own analyzer only recognizes a `@dataclass(frozen=True)` class as a pure constructor (`_empty_constructor` $\to$ `"record"` in [analyzer.py](../../../src/messpy/analyzer.py#L1560) and `_established_call` in [effects.py](../../../src/messpy/effects.py#L375)) if its body contains **only** `AnnAssign` statements with `None` or `ast.Constant` defaults (`Pass` and docstrings allowed), **no base classes** (so `Enum` subclasses are *not* recognized as pure constructors!), and **no methods**.
   - If you add methods, `field(default_factory=...)`, or tuple/frozenset non-Constant default expressions to a `@dataclass(frozen=True)` state type (or subclass `Enum`), any function in `src/messpy/` that constructs `MyState(...)` will treat that constructor call as an `UnknownEffect` (`unresolved call`) and `Storage(opaque=True)` during self-analysis, and classes with methods will also be subject to `LackOfCohesionOfMethods` ($\text{LCOM4} \le 1$)!
   - **Rule:** Keep state dataclasses pure data records (`AnnAssign` with `None` or literal `Constant` defaults; use `()` or `None` instead of `field(default_factory=...)` or `frozenset()`), and write state transitions as module-level functions `_step_*(state: _State, ...) -> _State`.

2. **PITFALL (Self-Analysis Breaker): Refactoring `_destination_file_mode` or `main` in [cli.py](../../../src/messpy/cli.py#L153-L158) and [cli.py](../../../src/messpy/cli.py#L750-L759).**
   - [verify_self_analysis.py](../../../scripts/verify_self_analysis.py#L93-L106) hardcodes AST inspection of `main` (requiring 3 literal defaults `sys.argv`, `sys.stdout`, `sys.stderr`) and `_destination_file_mode` (requiring direct `ast.Call` nodes to `report_file.stat`, `stat.S_IMODE`, and `os.umask` inside `_destination_file_mode`'s AST subtree, and asserting exact `UnknownEffect` findings on their max line numbers).
   - **Rule:** Do not extract `os.umask` out of `_destination_file_mode` into an external helper or context manager when addressing `M05`.

3. **PITFALL (Formal Verifier Breaker): Changing `_ConfiguredRule` or `_merge` signatures in [rulesets.py](../../../src/messpy/rulesets.py#L50-L56) and [rulesets.py](../../../src/messpy/rulesets.py#L485-L510).**
   - [.agents/skills/verify-ruleset-precedence/scripts/contracts.py](../../../.agents/skills/verify-ruleset-precedence/scripts/contracts.py#L1-L41) directly imports `LoadedRule, _ConfiguredRule, _merge` and symbolically executes them under CrossHair (`0.0.110`).
   - **Rule:** Preserve `_ConfiguredRule(rule, explicit_priority, explicit_properties)` and `_merge` or update `contracts.py` in lockstep and re-verify all 4 CrossHair contracts confirm over all paths.

4. **PITFALL (`M09` Lexical Lookup): False unification across the 4 scope resolvers.**
   - `callgraph.py` (`_resolve_bare_name`), `names.py` (`_resolved_record`), `analyzer.py` (`_ScopeChain.binding`), and `analyzer.py` (`_is_function_shadowed` / `_is_shadowed`) have subtle, intentional differences:
     - `callgraph.py` invalidates module-level callable bindings if *any* function in the module has a `global x` declaration that stores/deletes `x` (`index.rebound_globals` at [callgraph.py](../../../src/messpy/callgraph.py#L204-L215)), whereas `names.py` only checks module-scope assignments (`_scope_assigned`).
     - `_ScopeChain` classifies a module-level name that is both imported and assigned (e.g., `try: import x except ImportError: x = None`) as `"definition"` ([analyzer.py](../../../src/messpy/analyzer.py#L1962-L1968)), whereas `names.py` hides an import if the same scope assigns to that name ([names.py](../../../src/messpy/names.py#L212-L216)).
     - Class scopes are skipped when resolving free variables inside methods, *except* when evaluating expressions directly inside the class body (`_ScopeChain.for_node` at [analyzer.py](../../../src/messpy/analyzer.py#L1793-L1807), `_with_parent_scope` at [names.py](../../../src/messpy/names.py#L150-L159), and `allow_class` in `_scope_shadows_candidate` at [analyzer.py](../../../src/messpy/analyzer.py#L1281-L1284)).

5. **PITFALL (`M11` & `M26` & `M35` & `M37`): Subtle ordering and equality invariants.**
   - **`M11` (Comprehension lifetime):** In `[x for x in xs for x in f(x)]`, the second generator's `iter` (`f(x)`) is evaluated *before* the second `target` (`x`) shadows the first `x` ([analyzer.py](../../../src/messpy/analyzer.py#L2836-L2845)). Transitioning to `shadowed=True` before scanning `later_generator.iter` will cause false positives in `UnusedLocalVariable`.
   - **`M26` (Next-line suppression):** `# messpy-disable-next-line RuleA` skips over subsequent comment lines that have `DevelopmentCodeFragment` findings (`comment_finding_rules`) *unless* `RuleA` is in `comment_finding_rules[target_line]` ([analyzer.py](../../../src/messpy/analyzer.py#L4920-L4926)), and when targeting a decorator or `def` line, expands suppression across the entire multi-line signature (`header_lines`).
   - **`M35` (Duplicate dict keys):** `_duplicated_array_key_findings` ([analyzer.py](../../../src/messpy/analyzer.py#L2300-L2319)) relies on native Python `dict` key equality where `1 == True == 1.0` and `0 == False == -0.0`, and retains the *first* key's line number (`keys[value] = key` only on miss) even when a key appears 3+ times.
   - **`M37` (Observation history):** `_visit_call` ([ownership.py](../../../src/messpy/ownership.py#L940-L941)) emits a second `_Seen(id(node), flow.bindings)` *after* argument evaluation so that `ownership.value(arg, call)` observes side effects (such as `:=` or mutations) inside call arguments; `_observations(trace)` must remain last-seen-wins.
